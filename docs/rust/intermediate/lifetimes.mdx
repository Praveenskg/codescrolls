# Lifetimes

Lifetimes tell the compiler how long references are valid. Often inferred;
sometimes annotated.

## Why Lifetimes?

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() >= y.len() { x } else { y }
}
```

The output lives as long as both inputs (the shorter borrow).

## Structs Holding References

```rust
struct Excerpt<'a> {
    part: &'a str,
}

let novel = String::from("Call me Ishmael...");
let first = novel.split('.').next().unwrap();
let excerpt = Excerpt { part: first };
```

## Static Lifetime

```rust
let s: &'static str = "literal";
```

String literals live for the whole program. Avoid forcing `'static` on temporary
data.

## Elision Rules

In many functions Rust infers lifetimes. You annotate when relationships are
ambiguous.

## Common Pitfalls

- Fighting the checker by cloning instead of learning the relationship
- Overusing `'static` to silence errors
- Returning references to locals
