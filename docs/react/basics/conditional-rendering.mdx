# Conditional Rendering in React

**Conditional rendering** allows you to display different UI elements based on
certain conditions. React provides several ways to conditionally render
components.

---

## Why Conditional Rendering?

You often need to show different content based on:

- User authentication status
- Loading states
- Error states
- User permissions
- Feature flags
- Data availability

---

## If-Else Statements

The most basic way to conditionally render is using if-else statements:

```jsx
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <h1>Welcome back!</h1>;
  } else {
    return <h1>Please sign in.</h1>;
  }
}
```

### Early Return Pattern

```jsx
function UserDashboard({ user }) {
  // Early return for null/undefined
  if (!user) {
    return <div>Loading...</div>;
  }

  return (
    <div>
      <h1>Welcome, {user.name}!</h1>
      <p>Email: {user.email}</p>
    </div>
  );
}
```

---

## Ternary Operator

The ternary operator (`condition ? true : false`) is perfect for inline
conditional rendering:

```jsx
function LoginButton({ isLoggedIn }) {
  return <button>{isLoggedIn ? 'Logout' : 'Login'}</button>;
}
```

### Multiple Conditions

```jsx
function UserStatus({ status }) {
  return (
    <div>
      Status:{' '}
      {status === 'online'
        ? ' Online'
        : status === 'away'
          ? ' Away'
          : ' Offline'}
    </div>
  );
}
```

### Rendering Components

```jsx
function App({ isLoggedIn }) {
  return <div>{isLoggedIn ? <Dashboard /> : <LoginForm />}</div>;
}
```

## Logical AND (&&) Operator

Use `&&` when you want to render something only if a condition is true:

```jsx
function Mailbox({ unreadMessages }) {
  return (
    <div>
      <h1>Hello!</h1>
      {unreadMessages.length > 0 && (
        <h2>You have {unreadMessages.length} unread messages.</h2>
      )}
    </div>
  );
}
```

### Multiple Conditions

```jsx
function UserProfile({ user, isAdmin }) {
  return (
    <div>
      <h1>{user.name}</h1>
      {user.email && <p>Email: {user.email}</p>}
      {user.phone && <p>Phone: {user.phone}</p>}
      {isAdmin && <button>Admin Panel</button>}
    </div>
  );
}
```

### Beware of Falsy Values

```jsx
//  Bad - Will render "0" if count is 0
{
  count && <div>Count: {count}</div>;
}

//  Good - Explicitly check
{
  count > 0 && <div>Count: {count}</div>;
}

//  Also good
{
  count !== 0 && <div>Count: {count}</div>;
}
```

---

## Logical OR (||) Operator

Use `||` to provide fallback content:

```jsx
function UserName({ name }) {
  return <h1>{name || 'Guest'}</h1>;
}
```

### Nullish Coalescing (??)

```jsx
function Counter({ count }) {
  // Only falls back if count is null or undefined (not 0)
  return <div>Count: {count ?? 'No count'}</div>;
}
```

## Switch Statements

For multiple conditions, use switch statements:

```jsx
function StatusBadge({ status }) {
  let badge;

  switch (status) {
    case 'success':
      badge = <span> Success</span>;
      break;
    case 'error':
      badge = <span> Error</span>;
      break;
    case 'warning':
      badge = <span> Warning</span>;
      break;
    default:
      badge = <span>ℹ Info</span>;
  }

  return <div>{badge}</div>;
}
```

### Object Mapping (Cleaner Alternative)

```jsx
function StatusBadge({ status }) {
  const badges = {
    success: <span> Success</span>,
    error: <span> Error</span>,
    warning: <span> Warning</span>,
    info: <span>ℹ Info</span>,
  };

  return <div>{badges[status] || badges.info}</div>;
}
```

## Conditional Styles

### Inline Styles

```jsx
function Alert({ type }) {
  const styles = {
    padding: '10px',
    borderRadius: '5px',
    backgroundColor: type === 'error' ? '#ff0000' : '#00ff00',
    color: 'white',
  };

  return <div style={styles}>Alert message</div>;
}
```

### Style Objects

```jsx
function Box({ isHighlighted }) {
  const baseStyle = {
    padding: '20px',
    border: '1px solid #ccc',
  };

  const highlightStyle = {
    ...baseStyle,
    backgroundColor: '#ffeb3b',
    border: '2px solid #fbc02d',
  };

  return <div style={isHighlighted ? highlightStyle : baseStyle}>Content</div>;
}
```

## Rendering Lists Conditionally

```jsx
function UserList({ users, showEmptyState }) {
  if (users.length === 0 && showEmptyState) {
    return <div>No users found</div>;
  }

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

## Loading States

### Simple Loading

```jsx
function DataDisplay({ data, isLoading }) {
  if (isLoading) {
    return <div>Loading...</div>;
  }

  return <div>{data}</div>;
}
```

### Loading with Spinner

```jsx
function UserProfile({ user, isLoading, error }) {
  if (isLoading) {
    return (
      <div>
        <div></div>
        <p>Loading user data...</p>
      </div>
    );
  }

  if (error) {
    return (
      <div>
        <p>Error: {error.message}</p>
        <button onClick={retry}>Retry</button>
      </div>
    );
  }

  if (!user) {
    return <div>No user found</div>;
  }

  return (
    <div>
      <h1>{user.name}</h1>
      <p>{user.email}</p>
    </div>
  );
}
```

## Authentication Examples

### Protected Route

```jsx
function ProtectedRoute({ isAuthenticated, children }) {
  if (!isAuthenticated) {
    return <Navigate to="/login" />;
  }

  return children;
}

// Usage
<ProtectedRoute isAuthenticated={isLoggedIn}>
  <Dashboard />
</ProtectedRoute>;
```

### Role-Based Rendering

```jsx
function AdminPanel({ user }) {
  if (!user) {
    return <div>Please log in</div>;
  }

  if (user.role !== 'admin') {
    return <div>Access denied. Admin only.</div>;
  }

  return (
    <div>
      <h1>Admin Panel</h1>
      {/* Admin content */}
    </div>
  );
}
```

## Best Practices

### 1. **Keep Conditions Simple**

```jsx
//  Bad - Complex nested conditions
{
  isLoggedIn && user && user.isPremium && user.hasAccess && <PremiumContent />;
}

//  Good - Extract to variable
const canAccessPremium = isLoggedIn && user?.isPremium && user?.hasAccess;

{
  canAccessPremium && <PremiumContent />;
}
```

### 2. **Use Early Returns**

```jsx
//  Bad - Nested conditions
function Component({ data }) {
  return (
    <div>
      {data ? (
        data.items ? (
          <List items={data.items} />
        ) : (
          <div>No items</div>
        )
      ) : (
        <div>Loading...</div>
      )}
    </div>
  );
}

//  Good - Early returns
function Component({ data }) {
  if (!data) return <div>Loading...</div>;
  if (!data.items) return <div>No items</div>;

  return <List items={data.items} />;
}
```

### 3. **Extract Complex Conditions**

```jsx
//  Bad
{
  user && user.age >= 18 && user.hasLicense && !user.isSuspended && (
    <DriveButton />
  );
}

//  Good
const canDrive = user?.age >= 18 && user?.hasLicense && !user?.isSuspended;

{
  canDrive && <DriveButton />;
}
```

### 4. **Use Descriptive Variable Names**

```jsx
//  Bad
const x = user && user.role === 'admin';

//  Good
const isAdmin = user?.role === 'admin';
const canEditPost = isAdmin || post.authorId === user?.id;
```

## Common Mistakes

### 1. **Rendering Falsy Values**

```jsx
//  Wrong - Renders "0"
{
  items.length && <div>Items: {items.length}</div>;
}

//  Correct
{
  items.length > 0 && <div>Items: {items.length}</div>;
}
```

### 2. **Not Handling Null/Undefined**

```jsx
//  Wrong - Can crash if user is null
{
  user.name && <div>{user.name}</div>;
}

//  Correct - Use optional chaining
{
  user?.name && <div>{user.name}</div>;
}
```

### 3. **Too Many Ternaries**

```jsx
//  Bad - Hard to read
{
  status === 'loading' ? (
    <Spinner />
  ) : status === 'error' ? (
    <Error />
  ) : status === 'success' ? (
    <Success />
  ) : (
    <div>Unknown</div>
  );
}

//  Good - Use if-else or object mapping
function StatusDisplay({ status }) {
  if (status === 'loading') return <Spinner />;
  if (status === 'error') return <Error />;
  if (status === 'success') return <Success />;
  return <div>Unknown</div>;
}
```

---

## Summary

- Use **if-else** for complex logic with early returns
- Use **ternary operator** for inline conditional rendering
- Use **&&** for rendering when condition is true
- Use **||** or **??** for fallback values
- Use **switch** or **object mapping** for multiple conditions
- **Extract complex conditions** into variables
- **Handle null/undefined** with optional chaining
- **Avoid rendering falsy values** unintentionally
