## Why Next.js (Detailed)

Next.js continues to lead the React meta-framework space because it solves a
large set of cross-cutting concerns for production web apps: routing, server
rendering, image and font optimization, scale-friendly data fetching, and a
deployment story that maps directly to modern hosting platforms (Vercel,
Netlify, Fly, and cloud providers).

- Performance-first defaults: hybrid rendering, automatic code-splitting, and
  first-class image/font optimization.
- Developer ergonomics: file-system routing, simple data-fetching primitives,
  and conventions that reduce boilerplate.
- SEO and accessibility are easier because pages can be server-rendered with
  predictable metadata and HTML output.

In short: Next.js is pragmatic — it gives teams a safe set of defaults while
allowing opt-in complexity for advanced needs.

## App Router Fundamentals (Expanded)

The App Router (app/) is now the recommended way to organize routes. It uses
nested layouts and server-driven rendering to ship only the UI that changes.

Key concepts:

- Route segments: Each folder in `app/` maps to a route segment and may export
  `layout.tsx`, `page.tsx`, `loading.tsx`, `error.tsx`, and `not-found.tsx`.
- Layouts are composable: a child layout inherits and augments parent UI, so you
  can define shell UI once (header, footer, nav) and swap inner content.
- Server Components by default: components rendered on the server can fetch data
  and return HTML with minimal client JS.

Example structure and notes:

```text
app/
  layout.tsx          // Root layout: html, body, global providers
  page.tsx            // Home page
  dashboard/
    layout.tsx        // Dashboard shell (sidebar, header)
    page.tsx          // Dashboard index
    settings/
      page.tsx        // Nested route under dashboard
  api/
    health/route.ts   // Route handlers for APIs
```

Minimal `layout.tsx` with strict-mode-friendly providers:

```tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>
        {/* Global providers go here (theme, auth) */}
        {children}
      </body>
    </html>
  );
}
```

Tips:

- Prefer many small layouts for predictable CSS scoping and easier transitions.
- Use `loading.tsx` per segment to provide progressive loading UX.

## Server vs Client Components (Deep Dive)

Server Components (SC): rendered on server, can access secrets and DBs, and send
minimal HTML to the client. They cannot use hooks like `useState` or the DOM.

Client Components (CC): include event handlers, state, effects, and browser
APIs. CCs must opt into `'use client'` at the top of the file.

Architecture pattern:

- Keep layout and data-fetching in SCs. Wrap small interactive pieces (forms,
  widgets) in CCs.
- Use typed interfaces for props passed between SCs and CCs to document the data
  contract and reduce re-renders.

Example: server page renders a list and delegates comment form to a client
component.

```tsx
// server component
export default async function PostPage({
  params,
}: {
  params: { slug: string };
}) {
  const post = await getPost(params.slug); // server DB call
  return (
    <article>
      <h1>{post.title}</h1>
      <div dangerouslySetInnerHTML={{ __html: post.html }} />
      <CommentForm postId={post.id} /> // client component
    </article>
  );
}
```

```tsx
// CommentForm.tsx
'use client';
import { useState } from 'react';
export function CommentForm({ postId }: { postId: number }) {
  const [text, setText] = useState('');
  return (
    <form /* use server action or API */>
      <textarea value={text} onChange={e => setText(e.target.value)} />
      <button type="submit">Comment</button>
    </form>
  );
}
```

## Rendering Strategies (When to use which)

- Static (SSG): for marketing pages, docs — fastest for repeated traffic.
- Incremental Static Regeneration (ISR): static by default, revalidate every N
  seconds — good for content that changes occasionally.
- Server-side Rendering (SSR): `cache: 'no-store'` when you need per-request
  personalization or up-to-the-moment data.
- Streaming: use React streaming with server components to send the shell
  quickly and hydrate interactive parts as they load.

Example: fetch with revalidation

```tsx
const posts = await fetch('https://api.example.com/posts', {
  next: { revalidate: 300 },
}).then(r => r.json());
```

Use `no-store` or `cache: 'no-store'` for sensitive endpoints (user sessions,
payment status).

## Data Fetching and Caching (Patterns)

- Keep data fetching in server components or React server actions.
- Prefer fetch with `next: { revalidate }` for ISR and `cache: 'no-store'` for
  real-time data.
- Use edge functions or middlewares for geographically distributed caching and
  to keep latency low.

Resilience:

- Add timeouts and error handling to fetches.
- Provide fallback UI via `loading.tsx` and `error.tsx`.

## Server Actions (Best Practices)

Server Actions reduce boilerplate for form submissions and mutations but require
careful error handling and idempotency consideration.

Recommendations:

- Validate inputs server-side and return clear error shapes.
- Keep actions small and focused — delegate heavy work to services.
- Use optimistic UI sparingly; prefer revalidation after action completes.

```tsx
'use server';
import { createPostInDB } from '@/lib/db';

export async function createPost(formData: FormData) {
  const title = String(formData.get('title') || '');
  if (!title) return { error: 'Title required' };
  const post = await createPostInDB({ title });
  return { ok: true, post };
}
```

## API Route Handlers (When to prefer them)

Use route handlers when you need a web callback, webhooks, or an endpoint used
by external services. Keep public APIs idempotent and authenticated when
required.

```ts
// app/api/health/route.ts
import { NextResponse } from 'next/server';
export async function GET() {
  return NextResponse.json({ status: 'ok' });
}
```

## SEO in Next.js (Detailed)

- Use the Metadata API to generate canonical, OG, and structured data.
- Generate sitemaps on build or via an API route if content updates frequently.
- Ensure semantic structure (`h1` per page, correct heading hierarchy).

Example metadata with dynamic values:

```tsx
import type { Metadata } from 'next';
export async function generateMetadata({ params }): Promise<Metadata> {
  const post = await getPost(params.slug);
  return {
    title: post.title,
    description: post.summary,
    openGraph: { title: post.title, description: post.summary },
  };
}
```

## Project Structure (Opinionated)

Use `src/` with feature folders, `app/` for routes, `components/` for dumb UI,
`features/` for domain logic, and `lib/` for utilities and integrations.

Example:

```text
src/
  app/
  components/
  features/
  lib/
  styles/
  types/
```

## Performance Best Practices (Checklist)

- Prefer Server Components for initial render.
- Use `next/image` and `next/font`.
- Audit bundle size and tree-shake large libraries.
- Use HTTP caching (CDN) and appropriate Cache-Control headers.
- Measure Core Web Vitals and iterate.

## Common Mistakes (Longer list)

- Overusing `'use client'` and shipping unnecessary JS.
- Blocking rendering with long-running sync tasks.
- Not handling partial failures in streaming pages.
- Ignoring accessibility and semantic HTML.

## Deployment Checklist (Expanded)

1. Check environment variables and secrets management.
2. Run accessibility and performance audits (Lighthouse, Axe).
3. Harden headers (CSP, HSTS) via platform or middleware.
4. Setup observability: logging, tracing, Sentry/Opentelemetry.
5. Configure preview and staging environments for testing.
